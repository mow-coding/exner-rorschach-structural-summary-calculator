# [2026-02-15] v2.0.0 メジャーリリース

[한국어](./README.md) | [English](./README.en.md) | [日本語](./README.ja.md) | [Español](./README.es.md) | [Português (Brasil)](./README.pt-BR.md)

v2.0.0 は、v1.4.1 を新しいウェブアプリに移した最初のバージョン 2 リリースです。v1 の核心であったロールシャッハ Exner（CS）体系の構造要約計算の流れを維持しつつ、多言語画面、参照文書検索、BYOK 方式の AI 補助機能を追加しました。

このバージョンの最大の変化は、利用者が自分の OpenAI または Google の API キーを接続して AI 機能を使う BYOK（Bring Your Own Key）方式です。AI の利用費用は接続したアカウントで発生し、API キーは AI 接続が維持されている間だけ使われます。

## v1.4.1 から維持したもの

v1.4.1 の核心的な目的はそのまま維持しました。利用者はロールシャッハの反応を行単位で入力し、カード、反応領域、発達質、決定因、形態質、反応内容、特殊スコアなど構造要約の計算に必要な値を整理してから結果を計算できます。

v1 で提供していた構造要約の計算の流れ、結果の確認、CSV 書き出し、多言語対応も v2 に引き継ぎました。入力画面と結果画面は、モバイルとデスクトップで使いやすいウェブアプリの画面として再構成しました。

## 利用方法

主な画面は、採点画面、解釈アシスタント、参照文書、アカウント管理、バージョンアーカイブに分かれます。ログインしなくても基本的な計算機能と参照文書検索を使うことができ、AI 機能を使うにはログイン後に API キーを接続する必要があります。

## BYOK による AI 接続

v2 の AI 機能は BYOK 専用で動作します。アプリ内で AI クレジットやサブスクリプションを販売することはなく、利用者は OpenAI または Google のどちらかの API キーを接続できます。

API キーは AI 接続が維持されている間だけ使われ、ログアウトするか接続が期限切れになると削除されます。OpenAI のキーと Google のキーを間違った入力欄に入れると、すぐに案内します。

モデルは利用者が自分で選びません。ウェブアプリは、公開後一定期間が経って安定性が確認されたモデルの中からサービスが定めた最新モデルを自動的に使います。v2.0.0 時点では、OpenAI は GPT-5.4、Google は Gemini 2.5 Pro を既定モデルとしています。

AI プロバイダーがリクエストを拒否した場合も、エラーを一つにまとめてしまわないように整理しました。API キーが誤っている場合、支払いまたは利用量の上限の問題がある場合、その API キーでは選択されたモデルを使えない場合を区別して利用者に案内します。

## コーディングアシスタント

採点画面の AI はコーディングアシスタントとして整理しました。ここでいうコーディングはプログラミングではなく、ロールシャッハの反応を Exner（CS）体系の記号と範疇に符号化する過程を指します。

コーディングアシスタントは Ctrl/Cmd+J のショートカットで開けます。利用者が現在の採点画面に入力したシート全体が基本の文脈として渡され、特定の行を選択している場合はその行がより重要な文脈として強調されます。行を何も選択していない状態では、特定の中心行なしにシート全体の文脈だけを使います。

コーディングアシスタントは答えを自動的に確定しません。反応の領域、決定因、形態質、内容の範疇などを検討する際に、参照文書と入力内容をもとに可能な候補と根拠を説明します。

v2.0.0 は自動入力ボタンを提供しません。AI は候補と根拠を説明するだけで、最終的な符号化は臨床家が反応の文脈を検討して決めます。

## 解釈アシスタント

解釈アシスタントは、構造要約の数値 CSV をもとに解釈の会話を進めるための AI 画面です。利用者は構造要約の数値が入った CSV ファイルを添付し、年齢、性別、観察の文脈、臨床家がすでに考えている仮説や質問を併せて書いて、AI に検討を依頼できます。

解釈アシスタントは、構造要約の結果のパターンを説明し、利用者が立てた仮説を点検する補助的な役割を担います。正式な診断や最終的な解釈に代わるものではなく、最終判断は臨床家が担います。

## 参照文書

v2 は、ウェブアプリと AI アシスタントが参照する短い説明文書の集まりも併せて提供します。これらの文書は構造要約の計算、符号化、解釈過程の主要な概念を説明し、参照文書画面で直接検索できます。

参照文書は、ソウル臨床心理研究所と MOW が共同で制作し整理した資料をもとに構成しました。AI がどの知識を根拠に回答しているかを利用者が確認できるように公開することが目標です。これは AI 機能をブラックボックスにせず、利用者が根拠を確認しながら判断できるようにするという設計原則につながっています。

`+`、`-`、`v/+` のような符号を含む参照文書も正しく開きます。

## AI は臨床家の判断に代わりません

v2 は、AI が専門家に代わって判断するシステムではなく、臨床心理士と訓練生がより明確な根拠の上で検討し判断できるよう助けるシステムを目指しています。そのため AI 機能は二つだけに絞りました。採点画面ではコーディングアシスタント、別のチャット画面では解釈アシスタントです。

AI の回答は参考と補助のためのものであり、最終的な符号化と解釈は臨床家が判断します。

## セキュリティと個人情報

API キーと AI 会話の原文は、長期的なアカウント資料として保管されません。API キーは AI を接続している間だけ使われ、ログアウトするか接続が期限切れになると削除されます。

AI の利用費用は利用者が接続した API プロバイダーのアカウントで発生し、アプリ自体の決済やサブスクリプション機能はありません。

## 画面と使いやすさ

上部メニュー、言語選択、ライト・ダークモード、アカウント管理、バージョンアーカイブ、参照文書検索の画面を新しく構成しました。

採点画面では、行の選択、行の追加/削除、ショートカット、undo/redo の流れを整えました。選択された行は継続して強調表示され、選択状態によってコーディングアシスタントが受け取る文脈も変わります。

解釈アシスタント画面には CSV 添付ボタンとドラッグ＆ドロップによる添付を追加しました。テキストを貼り付ける方式だけでなく、構造要約の数値 CSV を添付してその内容を AI 会話の文脈として使えます。添付ファイルは一度に一つだけ受け付けるよう制限し、複数の資料が混ざって AI が誤った文脈を読むことを減らしました。

## 多言語対応

v2 は韓国語、英語、日本語、スペイン語、ポルトガル語の画面に対応します。言語はドロップダウンから選択でき、画面サイズや言語ごとの文字列の長さが異なっても配置が安定して維持されます。

## 製品の範囲

v2.0.0 の核心的な範囲は、構造要約の計算、参照文書、BYOK ベースのコーディングアシスタントと解釈アシスタントです。サービスが提供する AI クレジット、決済、サブスクリプション機能は含みません。
