# [2026-04-27] v2.0.1 バグ修正

[한국어](./README.md) | [English](./README.en.md) | [日本語](./README.ja.md) | [Español](./README.es.md) | [Português (Brasil)](./README.pt-BR.md)

v2.0.1 は、v2.0.0 公開後に見つかった利用上の問題を修正したリリースです。構造要約の計算、参照文書、BYOK ベースのコーディングアシスタントと解釈アシスタントという製品の範囲はそのまま維持されます。

## 要点

- 解釈アシスタントの入力の流れを、ファイル添付中心から構造要約の数値入力中心に整理しました。
- コーディングアシスタントと解釈アシスタントで、AI が長く話しすぎたり、利用者が制御しにくい形で画面が動いたりする問題を減らしました。
- AI 自動入力の流れを削除しました。符号化と解釈は、利用者が AI と会話しながら検討する方式だけを残しました。
- API キーの接続・終了画面が重なったり、必要な案内が表示されなかったりする問題を修正しました。
- ダークモードでトーストやシステム案内の吹き出しが透けて見えたり読みにくかったりする問題を修正しました。
- 参照文書の `+`、`-`、`v/+` のような符号を押したときにページが開かない問題を修正しました。
- サービス紹介、利用規約、プライバシーポリシーを現在の機能に合わせて修正しました。

## 解釈アシスタントへの構造要約データの入力

v2.0.0 では、解釈アシスタントは構造要約の CSV ファイルを添付する流れとして説明されていました。ファイル添付方式は、どのファイルを入れるべきか利用者が迷う可能性があり、AI がファイルの内容を安定して同じ方法で読めない余地がありました。

v2.0.1 では、結果画面でコピーした構造要約の数値を解釈アシスタントの専用入力欄に貼り付ける流れに整理しました。結果画面の構造要約の値をコピーした後、解釈アシスタントの入力欄の左にある小さな構造要約の数値入力欄に貼り付けて質問を始められます。

構造要約の数値を貼り付けると、原文全体の代わりに `入力済み` と表示されます。同じブラウザウィンドウを使っている間は、利用者が自分で消すか新しい値に置き換えるまで入力内容が維持されます。

また、解釈アシスタントがどんな資料でも受け付けてしまわないように、結果画面でコピーした構造要約の値の形式に合う入力だけを使うように制限しました。利用者が無関係なテキストを入れて会話を始めようとすると、結果画面の構造要約の値のコピー機能を使うよう案内します。

## 解釈アシスタントの回答

解釈アシスタントの回答は、利用者が続けて会話できる長さと形式に調整しました。v2.0.0 の直後は、回答が長くなりすぎたり、途中で途切れたり、数値を 1 行に多く並べすぎて読みにくかったりすることがありました。

解釈アシスタントは、1 回の回答で多くの主題を一度に広げず、`根拠となる数値` と `解釈の仮説` を分けて示します。

解釈アシスタントは `プロトコル` の代わりに、`検査資料`、`反応資料`、`構造要約資料` のようなより直感的な表現を使います。

## コーディングアシスタント

コーディングアシスタントは、採点画面で利用者が反応を符号化する際に会話で助けを得る機能です。v2.0.1 では、コーディングアシスタントが自動で行を埋めたり、ボタンで項目を適用したりする流れを削除しました。

コーディングアシスタントは、利用者が選択した行とシート全体の文脈をもとに、候補と根拠を会話で説明する役割だけを担うようになりました。利用者は AI の説明を参考にしつつ、実際の符号化の値は自分で検討して入力する必要があります。

採点画面で `Ctrl/Cmd+J` によりコーディングアシスタントを開ける流れは維持しました。行を何も選択していない状態では特定の中心行なしにシート全体だけを文脈として使い、選択された行があればその行をより重要な文脈として扱います。

## AI 自動入力の削除

`AI 自動入力` 機能を削除しました。この機能は、反応メモとカード情報をもとに現在の行の符号化項目を一度に埋めようとする流れでした。

ロールシャッハの符号化は、臨床家の検討と判断が必要な作業です。AI の提案を十分に検討せずに受け入れることを防ぐために自動入力機能を削除し、最終的な入力は臨床家が決めます。

その結果、v2.0.1 の AI 機能はより単純になりました。ウェブアプリ内の AI は、コーディングアシスタントと解釈アシスタントという二つの対話型補助機能だけを提供します。

## API キー接続画面

API キーは AI 接続が維持されている間だけ使われ、接続を終了すると削除されます。

OpenAI の入力欄に Google の API キーを入れたり、Google の入力欄に OpenAI の API キーを入れたりすると、正しい入力欄を案内します。

API 接続の終了ボタンとキー入力画面が互いに重なる問題も修正しました。API キーを接続していない状態で解釈アシスタントを開くと、必要な手順を案内します。

## AI モデルの選択

利用者はモデルを自分で選びません。ウェブアプリは、公開から少なくとも 1 か月以上経って安定性が確認されたモデルの中からサービスが定めた最新モデルを自動的に使います。

モデル選択の案内は必要な画面にだけ表示し、利用者が自分でモデルを選ばなければならないように見えないようにしました。

## ダークモードの案内

ダークモードで、システム案内の吹き出しや右上のトーストが透けて見えたり、背景と混ざって読みにくかったりする問題がありました。v2.0.1 では、トーストとチャット案内メッセージの背景色、枠線、文字色をより明確に表示します。

成功・警告・システム案内が他の画面要素に隠れたり背景と混ざったりしないように調整しました。

## AI 会話画面

コーディングアシスタントと解釈アシスタントの両方で、不要な案内文と重複メッセージを減らしました。AI モデル名、参照文書の一覧、項目適用ボタンのように、利用者の会話の流れを妨げたり過剰な機能のように見えたりする要素を削除しました。

AI が回答している間に画面が強制的に下へ流れ続け、利用者がスクロールを制御しにくかった問題も減らしました。利用者が以前の内容を見ている状況では、自動スクロールが過度に介入しないように整理しました。

回答を待つ間に表示される吹き出しの点の動きも、目障りにならないように和らげました。対話型ツールは利用者が長く見つめる画面であり、小さな動きでも疲労を生みうる点を反映しました。

## 開かなかった参照文書

参照文書には、`+`、`-`、`v/+` のように符号そのものが文書名に含まれる項目があります。v2.0.0 では、これらの符号を含む一部のリンクが開きませんでした。

`[符号化/発達質] v`、`[符号化/発達質] v/+`、`[符号化/形態質] +`、`[符号化/形態質] -` のような項目を押しても、正しい文書が開くようになりました。

## サービス案内

サービス紹介、利用規約、プライバシーポリシーを、実際に提供している機能に合わせて修正しました。アプリが独自の AI クレジット・決済・ストアを提供しているように見えた誤った案内も正しました。
