# 主な修正点

## *概要*

> **v1.4.0 のバグを修正しました。**

ウェブアプリに初めてアクセスしたときと再アクセスしたときに表示されるボタンが、正しく表示されるように修正しました。
>
- 以前は、再アクセスしても「サンプルデータで始める」ボタンが表示されるバグがありました。
    - 初回アクセス:「サンプルデータで始める」ボタンを表示
    - 再アクセス（保存データあり）:「自動保存した内容を読み込む」ボタンを表示
- 再アクセス時のモーダル画面をより整った見た目に改善しました。
    - 「作業を続ける」という題名を削除し、「前回作業した内容があります。」というメッセージだけを

        太い大きな文字で表示（同じことを不必要に二度言わないように改善）


> その他の改善
>
- 「もっと見る」タブのカードにマウスを乗せたとき、より目立つ効果を追加しました。
    - 影がより濃く表示される
    - カードの背後の背景画像がより鮮明に見える
    - カード内の文字はぼかされ、背景画像がより際立つ
- `styles.html` にあるべきスタイルの一部が `index.html` に残っていたものをすべて移し、

    コードをより整理しました。


これらの変更点は [Gems チャットボット](https://gemini.google.com/gem/1QDCPHshPvq5J9iIKeV-1Nvy0EFzKPN6Y?usp=sharing) にも反映されています。

## *詳細*

### *初回アクセスのモーダルのボタン表示ロジックの修正*

> **実装内容**
>
- **問題**
    - 初回アクセス時と再アクセス時の両方で「サンプルデータで始める」ボタンが表示される問題が発生
    - 再アクセス時に「サンプルデータで始める」ボタンを押しても、実際には自動保存された内容が読み込まれるバグが発生
- **解決方法**
    - 保存データがあるとき:「自動保存した内容を読み込む」ボタンを表示
    - 保存データがないとき:「サンプルデータで始める」ボタンを表示
    - `updateAllTexts()` 関数がモーダルの表示中にテキストを上書きしないように修正
    - すべての対応言語（韓国語、英語、日本語、スペイン語、ポルトガル語）で同じように動作するように改善

> **技術的な詳細**
>
- `updateAllTexts()` 関数で、モーダルがすでに表示されていればモーダルのテキストを更新しないガードを追加
- `handleScoringTabFirstLoad()` 関数で保存データの有無を確認してモーダルのテキストを設定
- 保存データがあるとき、`modalLoadBtn.textContent` を `t('modal_welcome_load_saved')` に設定
- 保存データがないとき、`modalLoadBtn.textContent` を `t('modal_welcome_load')` に設定
- `updateAllTexts()` 関数の内部でも保存データの有無を確認してモーダルのテキストを設定（モーダルの表示前に実行される場合に備えて）

**ファイル**: `index.html`（2387〜2426 行: updateAllTexts 関数、3974〜4060 行: handleScoringTabFirstLoad 関数）

### *初回アクセスのモーダル UI の改善*

> **実装内容**
>
- **題名の削除**
    - 保存データがあるとき、「作業を続ける」という題名を隠し、「前回作業した内容があります。」というメッセージだけを表示
    - 同じことを不必要に二度言わないように改善
- **メッセージのスタイル変更**
    - 保存データがあるとき、メッセージを太い黒の大きな文字（18px）で表示
    - 変更前: 小さな灰色の文字
    - 変更後: 太い黒の大きな文字（font-weight: bold、font-size: 18px、color: #212529）
- **初回アクセス時**
    - 保存データがないときは、従来どおり題名とメッセージの両方を表示
    - メッセージは既定のスタイル（小さな灰色）を維持

> **技術的な詳細**
>
- `handleScoringTabFirstLoad()` 関数で、保存データがあるとき `modalTitle.style.display = 'none'` を設定
- 保存データがあるとき、`modalMessage` にインラインスタイル（fontWeight、fontSize、color）を適用
- 保存データがないとき、`modalTitle.style.display = 'block'` を設定し、メッセージのスタイルを初期化
- `updateAllTexts()` 関数でも同じロジックを適用

**ファイル**: `index.html`（3987〜3993 行、4049〜4054 行、2403〜2409 行、2413〜2424 行）

### *静的スタイルのリファクタリング*

> **実装内容**
>
- **問題**
    - `index.html` にインラインスタイルが残っており、保守が難しい
    - CSS と HTML が分離されておらず、スタイルの修正時に複数のファイルを確認する必要がある
- **解決方法**
    - 静的スタイル（JavaScript で動的に制御しないスタイル）をすべて `styles.html` へ移動
    - JavaScript で動的に制御するスタイル（`display: none` など）は `index.html` に維持
- **移動したスタイル**
    - モーダルの題名/メッセージの `text-align: center` → `#reset-modal-title`、`#reset-modal-message`、`#ai-modal-title`、`#ai-modal-message` に追加
    - ガイドテキストのスタイル → `#Scoring_Summary > p` に追加
    - info-icon ラッパーの flex スタイル → `.row-controls > div` に追加
    - hr のスタイル → `#Notice hr` に追加
    - テーブルの width → `#list-table-body table` に追加
    - colgroup の width → `#list-table-body colgroup col:nth-child()` に追加

> **技術的な詳細**
>
- `index.html` からインラインスタイル属性を削除
- `styles.html` に該当セレクタの CSS 規則を追加
- モーダル関連のスタイルは 8.0 セクションに追加
- 「もっと見る」タブ関連のスタイルは 4.4、4.5 セクションに追加
- 共用コンポーネントのスタイルは 2.1 セクションに追加

**ファイル**:

- `index.html`（212〜213 行、224〜225 行、263 行、271〜275 行、287 行、325 行: インラインスタイルの削除）
- `styles.html`（1306〜1311 行: モーダルのスタイル、655〜666 行: テーブルのスタイル、667〜669 行: hr のスタイル、244〜250 行: 共用コンポーネントのスタイル）

### *「もっと見る」タブのカードの hover 効果の改善*

> **実装内容**
>
- **影の効果の強化**
    - 変更前: `box-shadow: 0 4px 8px rgba(0,0,0,0.1)`
    - 変更後: `box-shadow: 0 8px 24px rgba(0,0,0,0.25)`（より濃く大きな影）
- **背景画像の鮮明化**
    - hover 時に背景画像の opacity を 0.12 から 0.35 に増加
    - `filter: saturate(1.2) contrast(1.1)` を適用して色の鮮やかさを向上
- **文字のぼかし効果**
    - hover 時にカード内の文字へ `filter: blur(2px)` と `opacity: 0.6` を適用
    - 背景画像がより際立つように文字をぼかす
- **遷移効果**
    - すべての効果に `transition` を適用して滑らかなアニメーションを実現

> **技術的な詳細**
>
- `.link-button:hover` に影、背景画像の opacity、filter の効果を追加
- `.link-button:hover::before` に filter の効果を追加（背景画像の鮮明化）
- `.link-button:hover > *` に filter と opacity の効果を追加（文字のぼかし）
- すべての効果に `transition` 属性を追加（0.25s ease）

**ファイル**: `styles.html`（1357〜1375 行: hover 効果）
